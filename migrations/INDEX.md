## 🚀 Quick Start

### New Developer Setup

```bash
# 1. Clone repository and navigate to project
cd seafarer-management

# 2. Apply all migrations
chmod +x migrations/apply_all_migrations.sh
./migrations/apply_all_migrations.sh

# 3. Verify
psql $DATABASE_URL -c "\d recruitment_candidates"

# 4. Start application
npm run dev
```

```bash

psql $DATABASE_URL -f migrations/0001_add_is_delete_to_recruitment_candidates.sql
```

## 📋 Migration Order (Critical)

Migrations must be applied in this exact order:

1. **0000_stiff_archangel.sql** - Base schema
2. **PHASE2_DATABASE_MIGRATION.sql** - Phase 2 additions
3. **0001_add_is_delete_to_recruitment_candidates.sql** - Soft delete

**Why order matters:**
- 0000 creates the recruitment_candidates table
- 0001 adds the is_delete column to that table
- If you run 0001 before 0000, it will fail (table doesn't exist)

## 🆘 Troubleshooting

### Error: "relation 'recruitment_candidates' does not exist"
**Solution:** Apply base schema first
```bash
psql $DATABASE_URL -f migrations/0000_stiff_archangel.sql
```

### Error: "column 'is_delete' does not exist"
**Solution:** Apply soft delete migration
```bash
psql $DATABASE_URL -f migrations/0001_add_is_delete_to_recruitment_candidates.sql
```

### Error: "column 'is_delete' already exists"
**This shouldn't happen** - our migrations are idempotent (safe to run multiple times)

If it does happen:
```bash
# Check column status
psql $DATABASE_URL -c "\d recruitment_candidates" | grep is_delete
```
