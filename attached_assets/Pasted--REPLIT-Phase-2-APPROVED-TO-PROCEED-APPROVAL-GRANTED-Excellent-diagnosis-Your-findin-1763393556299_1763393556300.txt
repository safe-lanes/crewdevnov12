## BUSINESS REQUIREMENTS CLARIFICATION

### 1. Company Processing Module

**Purpose:** Handle crew recruitment and onboarding processing workflow

**Requirements:**
- **B7 Section:** This refers to a specific documentation section in maritime crew processing. Treat it as a flexible JSON structure where different fields can be added based on company needs. Include at minimum:
  - Medical clearance status
  - Document verification status
  - Training completion status
  - Flag state requirements
  
- **Comments:** Should support multiple comments with timestamps and author tracking. Structure as JSON array:
  ```json
  [
    {
      "text": "Comment text",
      "author": "User name",
      "timestamp": "2025-11-17T10:00:00Z"
    }
  ]
  ```

- **Approvals:** Multi-level approval workflow. Structure as JSON with approval stages:
  ```json
  {
    "stage1": {"status": "approved", "approver": "Manager Name", "date": "..."},
    "stage2": {"status": "pending", "approver": null, "date": null}
  }
  ```

- **Attachments:** Store file metadata (we'll handle actual file uploads separately):
  ```json
  [
    {
      "filename": "passport.pdf",
      "fileType": "document",
      "uploadDate": "...",
      "uploadedBy": "...",
      "fileSize": 1024000,
      "filePath": "/uploads/..."
    }
  ]
  ```

### 2. Promotion Forms Module

**Purpose:** Track crew member promotion requests and approval workflow

**Requirements:**
- Link to crew_members table
- Track current rank → proposed rank
- Include justification text (why promotion is deserved)
- Support approval workflow (pending → approved/rejected)
- Track submission date, review date, effective date
- Store reviewer comments
- Link to appraisal results if relevant

**Status Values:** draft, submitted, under_review, approved, rejected

### 3. Office Matrix

**Purpose:** Show vessel manning matrix - which positions are filled vs vacant

**Requirements:**
- For each vessel, show:
  - Rank/Position name
  - Required count (how many crew needed)
  - Current count (how many assigned)
  - Vacant count (required - current)
  - Names of currently assigned crew members

This should aggregate data from vessel_planning and crew_members tables.
