# REPLIT: Fix Recruitment Application "Save as Draft" Creating Duplicates

## 🐛 ISSUE #1: Save as Draft Creates Duplicate Records

### PROBLEM STATEMENT

In the Recruitment Application Form, clicking "Save as Draft" **always creates a NEW record** instead of updating the existing draft. This happens when a user progresses through the multi-step form (stepper).

---

## 📸 CURRENT BEHAVIOR (INCORRECT)

**Scenario:**
1. User opens recruitment form → Starts new application
2. Fills "Part A1: Seafarers' Particulars" → Clicks "Save Draft" button
   - ✅ POST → `/api/recruitment-candidates` 
   - ✅ Returns ID: `2025-11-18-1763443726289`
3. User moves to "Part A2: Travel & ID Documents" → Clicks "Save & Continue"
   - ❌ POST → `/api/recruitment-candidates` (WRONG!)
   - ❌ Creates NEW record with NEW ID: `2025-11-18-1763443890123`
4. User moves to "Part A3: Training & Certificates" → Clicks "Save & Continue"
   - ❌ POST → `/api/recruitment-candidates` (WRONG AGAIN!)
   - ❌ Creates ANOTHER record with NEW ID: `2025-11-18-1763444001234`

**Result:** Database has 3+ duplicate records for the same applicant!

---

## ✅ EXPECTED BEHAVIOR (CORRECT)

**Scenario:**
1. User opens recruitment form → Starts new application
2. Fills "Part A1: Seafarers' Particulars" → Clicks "Save Draft"
   - ✅ POST → `/api/recruitment-candidates`
   - ✅ Returns ID: `2025-11-18-1763443726289`
   - ✅ **Frontend STORES this ID** (in component state/context)
3. User moves to "Part A2: Travel & ID Documents" → Clicks "Save & Continue"
   - ✅ PATCH → `/api/recruitment-candidates/2025-11-18-1763443726289` (CORRECT!)
   - ✅ Updates the SAME record
4. User moves to "Part A3: Training & Certificates" → Clicks "Save & Continue"
   - ✅ PATCH → `/api/recruitment-candidates/2025-11-18-1763443726289` (CORRECT!)
   - ✅ Updates the SAME record
5. User continues through all steps using the SAME ID
6. **Only when user clicks "Create New Applicant" should POST be used again**

**Result:** Only 1 record in database, progressively updated through the stepper.

---

## 🔍 ROOT CAUSE

The frontend component is **NOT storing/tracking the candidate ID** after the first save. Every save button click triggers a POST request instead of checking if an ID already exists and using PATCH.

---

## 🎯 REQUIRED FIXES

### Fix 1: Frontend - Store Candidate ID After First Save

**File to modify:** `client/src/components/RecruitmentApplicationForm.tsx` (or similar)

**Current logic (WRONG):**
```typescript
// Every save calls POST
const handleSave = async () => {
  const response = await fetch('/api/recruitment-candidates', {
    method: 'POST',  // ❌ Always POST
    body: JSON.stringify(formData)
  });
  const data = await response.json();
  // ID is received but NOT stored ❌
};
```

**Fixed logic (CORRECT):**
```typescript
// Add state to track candidate ID
const [candidateId, setCandidateId] = useState<string | null>(null);

const handleSave = async () => {
  let response;
  
  if (candidateId) {
    // Update existing draft (PATCH)
    response = await fetch(`/api/recruitment-candidates/${candidateId}`, {
      method: 'PATCH',  // ✅ Update existing
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(formData)
    });
  } else {
    // Create new draft (POST)
    response = await fetch('/api/recruitment-candidates', {
      method: 'POST',  // ✅ Create new
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(formData)
    });
    
    const data = await response.json();
    setCandidateId(data.id);  // ✅ Store ID for future updates
  }
};
```

**Expected PATCH endpoint (backend):**
```typescript
app.patch("/api/recruitment-candidates/:id", async (req, res) => {
  try {
    const { id } = req.params;
    const result = updateRecruitmentCandidateSchema.safeParse(req.body);
    
    if (!result.success) {
      return res.status(400).json({ 
        error: "Invalid data", 
        details: result.error.issues 
      });
    }
    
    const updated = await storage.updateRecruitmentCandidate(id, result.data);
    
    if (!updated) {
      return res.status(404).json({ error: "Candidate not found" });
    }
    
    res.json(updated);
  } catch (error) {
    console.error('Error updating candidate:', error);
    res.status(500).json({ error: "Failed to update candidate" });
  }
});
```
