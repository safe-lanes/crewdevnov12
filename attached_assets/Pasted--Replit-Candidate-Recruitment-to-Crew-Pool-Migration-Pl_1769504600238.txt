# Replit: Candidate Recruitment to Crew Pool Migration Plan

## Context

We have upgraded our backend architecture from a legacy system (in `CrewingSamiksha` folder) to a new normalized database structure (in `crewingarchitecturev2` folder). The key change is:

**Legacy System**: When a candidate was recruited, their data was transferred to `crew_members` table with multiple TEXT columns storing JSON strings (documents, visas, education, licenses, trainingCourses, seaService, medicals, children, etc.)

**New System**: The JSON columns have been split into 66+ normalized tables with proper relationships, foreign keys, and audit trails.

---

Analyze both codebases and provide a detailed implementation plan for the **Candidate to Crew Pool Transfer** functionality in the upgraded backend.

## Requirements for the Plan

### 1. Data Transfer Mapping
Create a complete mapping of:
- Which recruitment tables map to which crew pool tables
- Field-by-field mapping between source and destination
- Handle any field transformations needed
- Handle attachment file references

### 2. Transfer Service Implementation
Design the `transferFromRecruitment()` function to:
- Validate candidate status (must be "Hired" or appropriate status)
- Use database transactions for atomicity
- Copy data from all relevant cand_* tables to crew_* tables
- Preserve the `source_rec_can_uuid` linkage
- Handle attachments (copy file references or actual files)
- Generate new UUIDs for crew pool records
- Set initial crew status as "active", availability as appropriate

### 3. API Endpoint Design
- Define request/response structure for POST `/api/v2/crew-pool/crew/transfer`
- Include validation rules
- Error handling for edge cases (duplicate transfer, missing data)

### 4. Audit & Lineage
- Ensure `source_rec_can_uuid` is properly set
- Track who performed the transfer (`created_by_uuid`)
- Handle soft deletes properly

### 5. Edge Cases to Handle
- Candidate already transferred (prevent duplicates)
- Missing optional data (not all candidates have all fields)
- Attachment file handling
- Partial failures (rollback strategy)
