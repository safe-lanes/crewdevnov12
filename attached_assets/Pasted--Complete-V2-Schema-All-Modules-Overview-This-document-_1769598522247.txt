# Complete V2 Schema: All Modules

## Overview

This document outlines the complete V2 architecture for Admin, Vessel, Crew Pool, and Rotation modules with proper foreign key relationships.

**Design Principles:**
- UUID identifiers with serial PKs
- Soft deletes (`is_deleted`)
- Audit columns (`created_at`, `updated_at`, `created_by_uuid`, `updated_by_uuid`)
- Sync flag (`is_sync`)
- Proper FK constraints to master tables
- Minimal JSON (array columns allowed where normalization adds unnecessary complexity)

## Data Flow

```
STEP 1: Admin - Create Vessel Revision
├── T1: vessel_revisions_v2 (CREATE revision header)
└── T2: vessel_revision_ranks_v2 (DEFINE ranks for vessel)
         └── actual_manning: text[] (crew_uuids)
           │
           ▼
STEP 2: Vessel - Planning
├── T3: vessel_planning_v2 (VIEW/MANAGE crew positions)
│        ├── References T1.active_revision_uuid
│        └── References C1.crew_uuid
└── T4: vessel_planning_attachments_v2 (HANDOVER docs)
           │
           ▼
STEP 3: Rotation - Create Plan
├── T5: rotation_drafts_v2 (CREATE plan header)
├── T6: rotation_draft_vessels_v2 (SELECT vessels)
├── T7: rotation_draft_ranks_v2 (SELECT ranks)
└── T8: rotation_entries_v2 (PROPOSE crew from C1)
           │
           ▼
STEP 4: Rotation - Approval & Deploy
├── T8: rotation_entries_v2 (UPDATE proposal_status)
├── T3: vessel_planning_v2 (INSERT/UPDATE crew assignment)
├── C2: crew_assignments (INSERT is_current = true)
└── T9: rotation_archive_v2 (INSERT result = 'Deployed')
           │
           ▼
STEP 5: Sign-Off (Later)
├── T3: vessel_planning_v2 (UPDATE is_archived = true)
├── C2: crew_assignments (UPDATE is_current = false)
└── C3: crew_sea_service (INSERT historical record)
```
