Implement Oil Major Officer Matrix Compliance Engine (with Excel Mapping)
Context:
We are developing the "Oil Major Officer Matrix" submodule in the Crewing module of our Maritime ERP. This functionality ensures that all officers assigned to a tanker meet the experience and qualification requirements of a specific oil major (e.g., BP, ADNOC, Chevron, etc.).
✅ Current Setup Already in Place
Database (PostgreSQL):
Ranks are stored with Rank ID, Rank, and Rank Label
Each officer's service breakdown is recorded under:
years_with_operator (Company)
years_in_rank
years_on_tanker_type
years_on_all_tankers
years_as_oow
time_onboard_months
language_proficiency
UI:
Displays per-officer matrix with these fields
Shows oil major rule vs. actual matrix value and visual compliance indicator (✓ or ✕)
🎯 Objective
Create a configurable rule engine and data master (via JSON or DB table) that stores the specific Officer Matrix requirements for each oil major, and dynamically validates the current crew matrix for a vessel against them.
This should:
Match officer data to Oil Major-specific rules
Perform validation per oil major for:
Combined team thresholds (e.g., Master + Chief Officer ≥ 2 years with operator)
Individual thresholds (if applicable)
Rank-pair rules (e.g., 3rd + 4th Engineer)
Minimum days gap between joining dates
Language proficiency minimum
🧩 Input Rules: Excel Sheet-Based Configuration
You will receive an Excel sheet that contains the rule definitions per oil major. The categories include:
Years with Operator
Years in Rank
Years on This Type of Tanker
Years on All Types of Tankers
Years as Watch Officer / Engineer
Date Joined (minimum overlap between replacements)
Language Proficiency
Each row in the Excel file represents a rule for a rank-pair or rank group under a specific oil major.
📝 How to Interpret the Excel Sheet (Rule Extraction Logic):
Filter Column A for the target Oil Major (e.g., “BP”).
For each rule row that appears:
The experience category is indicated in the column section (e.g., “Years in Rank”).
The applicable ranks (e.g., “Master + Chief Officer”, “Chief Eng + 2nd Eng”) are specified in the “For Calculation” column.
The threshold value is listed in “Required Value Minimum”.
The label explains the rule in plain text (e.g., “Combined aggregate for Master and C/O shall not be less than 2 years.”)
Refer to the attached image titled “Excel to UI Mapping” to see how the rule rows visually correspond to the structured display screen.
🧠 What You Need to Build:
Rule Config Schema
Define a JSON schema that stores all rules per oil major, using combined and individual logic where relevant.
{
  "BP": {
    "teamCriteria": {
      "Master + Chief Officer": {
        "min_years_with_operator": 2,
        "min_years_in_rank": 2,
        "min_years_on_all_tankers": 6
      },
      "Chief Engineer + Second Engineer": {
        "min_years_with_operator": 2,
        "min_years_on_type": 3,
        "min_years_on_all_tankers": 6
      }
    },
    "joining_overlap_days": {
      "Master_ChiefOfficer": 14,
      "ChiefEngineer_SecondEngineer": 14
    },
    "min_language_level": "Good"
  }
}
Rule Parsing Logic from Excel:
Loop through all rows for a given oil major
Categorize rules by experience type (e.g., Operator, Rank, Tanker Type, All Tankers, OOW, Join Date)
Parse rank pair (e.g., “Chief Engineer + Second Engineer”) to define the key
Populate the rule object as above
Compliance Validator:
Accept vessel_id or crew matrix input
Pull assigned officers and match against oil major rules
For combined values, sum across specified ranks using lowest experience per rank when multiple crew in same rank are onboard
Evaluate all required fields and return a Boolean flag + detailed per-rule result (pass/fail)
🧮 Validation Rules (Logic Details)
If a rule is for a combined rank (e.g., “Master + Chief Officer”), take the lowest value per rank onboard and sum them
If a rule is for an individual rank (e.g., “Master ≥ 3 years in rank”), apply it directly
If multiple junior officers exist, always use the least experienced officer in that rank
For date-based rules (e.g., 14 days gap between join dates), use time_onboard_months or actual joining timestamps
Language compliance: officer's recorded level (e.g., “Good”, “Fair”) must meet or exceed rule
📦 Final Deliverables
JSON/DB structure to store rules per oil major
Parser function to ingest the Excel and convert into config
Compliance check function (input: crew matrix + oil major; output: rule-by-rule pass/fail)
Optional: JSON API for frontend to consume and display compliance summary
