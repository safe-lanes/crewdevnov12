# Mobile device security controls

## Implemented in source configuration

- Authentication state is stored only through `expo-secure-store` with `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`; it is not migratable to another device.
- Android application backup is disabled. SecureStore's Android backup configuration remains enabled so its encrypted entries are excluded correctly from backup rules generated by Expo.
- iOS default file protection is `NSFileProtectionComplete`.
- No application deep-link scheme, WebView, clipboard integration, contacts, location, microphone, camera, background service, or tracking SDK is declared by the mobile source.
- API responses use an in-memory React Query cache and are cleared at logout.

## Additional controls now implemented

- Screenshot and screen-recording blocking uses `expo-screen-capture`.
- Server-enforced TOTP MFA uses encrypted secrets and single-use recovery codes, with in-app enrollment and login challenge handling.

## Dependency-gated / not yet implemented

- Optional biometric step-up needs product recovery design. It is a local convenience control and must not replace server MFA.
- Root/jailbreak and platform-integrity signals require native/infrastructure support and must never be treated as authentication.
- Generated AndroidManifest.xml, Info.plist, entitlements and signed artifacts must be inspected after the final native build. Source configuration alone is not release evidence.

Temporary files created by the system document/image pickers and shared downloads require final-device lifecycle tests. No claim is made that OS/provider copies are erased by the application.
